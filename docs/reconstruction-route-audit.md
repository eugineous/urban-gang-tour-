# Reconstruction route and operating-system audit

Source audit: 11 October 2026, Africa/Nairobi. This records the source inspected at the start of reconstruction, plus the bounded Events-tool corrections described below. It is not evidence that production data, provider credentials, legal permissions, performance thresholds, or every browser journey have been verified.

Current implementation checkpoint: see `reconstruction-execution.md`. The matrix below is the starting-state inventory, not an assertion that each listed gap remains unchanged. This bundle adds `/cookie-policy`, lossless validated ticket capacities/order limits and matching staff controls; replaces the homepage/portfolio/presenter/event presentation; and connects optional merchandise names through the existing order and production paths. Full Website Studio, a unified event root, crew planning, CRM consolidation and decision-grade reporting remain incomplete.

The filesystem contains 62 Next.js page modules and 98 `/api` route handlers. Public page wrappers generally use `RenderedPage → HostedSite → Site`; shop, booking, commerce, document, customer, and organizer workflows retain their existing dedicated implementations. The operating system is currently named **Control Room** in the product; the brief's **Rails** means that operating system, not the Ruby on Rails framework.

Disposition: preserve existing URLs, transaction contracts, customer records, and owned media. Improve the shared presentation and working modules incrementally. Consolidate overlapping content internally without deleting the existing entry points. Dynamic route rows below describe a route family, not a promise that an unpublished or nonexistent record has a live page.

The inspected `tourEvent.save` API replaces the whole editable event record. The previous Pin/Unpin/Restore shortcuts supplied only a partial record and could blank the date, venue, media and description. The Events module correction now sends all editable fields when changing priority, and Restore opens the existing form for review before publication. New events start as drafts, all lifecycle states retain their real labels, public visibility is distinguished from ticket eligibility, and loading/failure/empty states are distinct.

A separate contract gap remains in the inspected API: ticket tiers are normalized to `{name, price}` during `tourEvent.save`, while `ticket-inventory.ts` and `event-truth.ts` consume `capacity` and per-order limits. A full event save can therefore remove existing tier inventory metadata. This needs a lossless validated API contract and matching inventory controls; it must not be disguised by an “available” badge or solved by inventing stock.

## Privacy, cookie and legal surfaces

`CookieConsent` starts optional `/api/track` page views only after `ugt-consent=yes`; optional Google Analytics and AdSense loaders follow the same choice. The footer dispatches `ugt-open-cookie-settings` so visitors can revisit the choice. The banner is suppressed on admin, checkout and payment-return paths. Necessary session/abuse-prevention cookies, cart/display preferences and optional tracking must be explained separately. There is no standalone `/cookie-policy` page in this route snapshot.

The account screen exposes own-data export and a deletion-request pathway. `/admin/privacy` allows owner review and recorded resolution; it explicitly does not claim that closing a request erases financial records. Verified retention schedules, processor/storage statements, execution records and independent Kenyan legal approval are outstanding evidence, not assumptions. Ticket public verification is deliberately separate from permissioned gate access to holder contacts.

School filming permissions require an operational release/guardian/institution model. The ticket terms' general crowd-filming clause does not establish that those permissions exist for every child. No document, client name, archive appearance, old planning record or logo alone proves current authorization or a completed event.

## Verification boundary

This matrix comes from filesystem inventory and source inspection. It identifies work and acceptance criteria, not completion of the whole autonomous-reconstruction directive. End-to-end commerce, real admin/organizer role combinations, real provider callbacks, production media bindings, legal review, load testing and measured accessibility/performance still require explicit test evidence. Public deployment and main-branch merge are not performed by this audit.
